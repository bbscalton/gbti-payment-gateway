Use the app

Run the cloud demo against the live Worker and Firestore status mirror.

  1. Open the project in Android Studio Hedgehog+ (JDK 17+, SDK 34/35). Folder: Paymentgateway
  2. Select the cloudDebug build variant (product flavor cloud). It points at https://gbti-payment-gateway.neuereatec.workers.dev/
  3. Place app/google-services.json locally (do not commit). Refresh with Firebase CLI if needed: 
    npx -y firebase-tools@latest apps:sdkconfig ANDROID ^
  1:1036768290031:android:858b2df3b28d3f8baca71a ^
  --project gbti-payment-gateway -o app/google-services.json
  4. Run on an emulator or device. Create an order → pay → complete card entry on the hosted checkout page.

Build the APK

Produce an installable cloudDebug APK on Windows without shipping secrets.

Gradle (fastest)

cd C:\Users\Administrator\AndroidStudioProjects\Paymentgateway
.\gradlew.bat assembleCloudDebug

Output APK: app\build\outputs\apk\cloud\debug\app-cloud-debug.apk 

.\gradlew.bat assembleCloudRelease

Release APK (unsigned or with your keystore config): app\build\outputs\apk\cloud\release\app-cloud-release-unsigned.apk — or a signed APK if signing is configured.

Android Studio

  1. Build → Select Build Variant → choose cloudDebug (or cloudRelease).
  2. Build → Build Bundle(s) / APK(s) → Build APK(s), or
  3. Build → Generate Signed Bundle / APK → APK → pick your keystore → select the cloud flavor.

Prefer publishing the APK via GitHub Releases rather than committing binaries into git.

Safety notes

This stack is educational sandbox only.

  • Not affiliated with live GBTI production systems. No real funds move.
  • Never store PAN, CVV, or expiry in the app, GitHub, D1, KV, or Firestore.
  • Orders become paid only after a verified HMAC webhook.
  • Do not commit google-services.json, .env, or service-account keys.
